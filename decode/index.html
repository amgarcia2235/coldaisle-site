What it cannot decode.

  • OEM records. Any record type other than 02h is in the board maker's own format, which the IPMI standard does not describe. The decoder says so and shows the bytes for the maker's support. It does not guess.
  • OEM event types. Event types 70h to 7Fh are named by their sensor type only.
  • Sensor names and readings. A raw record carries a sensor number, not a name, and the bytes for a reading need the board's sensor data records to convert. So you see "Fan sensor 0x41", not "FAN4".
  • Your board's specifics. The guidance is general. The board maker's manual has the last word.

Where the records come from.

Read one record by ID with ipmitool. The reply starts with two bytes for the next record ID. Paste the 16 bytes after them.

ipmitool -I lanplus -H "$BMC" -U "$BMC_USER" -E raw 0x0a 0x43 0x00 0x00 0x01 0x00 0x00 0xff

More commands are on the ipmitool cheat sheet. The Cold Aisle app reads the log straight from the BMC, with sensor names and readings filled in.
